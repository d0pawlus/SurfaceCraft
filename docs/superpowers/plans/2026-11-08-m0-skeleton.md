# M0 — szkielet: plan

> Źródło: design doc §8 (M0), §9 (konwencje), spike §3. Gałąź `m0-skeleton`.

## Zakres
1. Workspace wg spike §3.1: `resolver = "3"`, `crates/*` + `apps/*` + `xtask`, edition 2024, MSRV 1.95,
   pakiety `surfacecraft-<crate>`, profile dev/ci/release, lints (`unsafe_code = "forbid"`, deny
   unwrap/expect/panic/todo/unimplemented/unreachable w korzeniach crate'ów).
2. Warstwy: L0 `geom`; L1 `kernel`, `fit`, `align`, `sketch`; L2 `deviation`, `doc`; L3 `io`; L4 `engine`;
   L5 `ui-egui`, `mcp` (+ `ai` w M6); apps. `cargo xtask layers` (tabela, `INTRA_LAYER_ORDER`, UI tylko od L5,
   solidcore tylko w `kernel`).
3. `geom`: typy f64 (nalgebra), `Mesh`, `KdTree`, `Bvh` (closest point, ray cast), `Transform`, `Rng`,
   `synth` (skany syntetyczne z prawdą bazową — korzeń korpusu poziomu 1).
4. `kernel`: pin `rev` solidcore `b9c02da` (sprawdzony w spike), adapter przez rekord (`Brep`), prymitywy,
   fillet/chamfer, objętość, tessellacja przez `solidcore-tess`; **smoke test box → fillet → to_record**.
5. `io`: STL (bin/ASCII), OBJ, PLY (ASCII/LE/BE) — import jako wrogie wejście (limity, kontrola liczności vs
   długości danych, fuzz `hostile_bytes_never_panic`), eksport STL/OBJ/PLY.
6. `doc`: `Document` (Arc na ciężkich danych), `History` (undo/redo przez migawki), format projektu.
7. `engine`: `Session`, `CommandSpec` (`area.verb`, schematy JSON wejścia/wyjścia przez schemars, `undoable`),
   rollback przy błędzie, `catch_unwind`, skrypty `{"commands": [...]}`, `hostile_params_never_panic`.
8. `ui-egui`: menu, lista obiektów, paleta komend z edytorem parametrów JSON, log (eksport jako skrypt),
   viewport wgpu; test GUI (egui_kittest) — kliknięcia wykonują te same komendy, log odtwarza się w CLI.
9. Apps: `surfacecraft` (desktop), `surfacecraft-cli` (`run`, `exec`, `commands`, `describe`, `licences`),
   `surfacecraft-web` (eframe WebRunner — pełny web w M6).
10. Pliki repo i `cargo xtask ci` = fmt → assets → licences → layers → app-geometry → clippy → wasm → test;
    GitHub Actions (ubuntu: pełne ci; windows: testy; cargo-deny: sources/bans/licences).

## Decyzje buildera (§10) podjęte w M0
- **Format projektu:** JSON (`surfacecraft-project`, wersja 1) z siatkami jako base64 LE — czytelny dla agentów
  i diffów, a siatka zajmuje ~1/3 tego, co lista liczb. Zmiana na binarny kontener możliwa przez numer wersji.
- **`storytold/craft-libs`:** nie używamy w M0 — każda zależność git poza solidcore wymagałaby wpisu
  w `allow-git`; egui wystarcza. Do ponownej oceny przy wydaniach (craft-update).
- **Viewport:** render offscreen (kolor + głębia) w `prepare` egui-wgpu i blit do przebiegu egui. Niezależny od
  bufora głębi okna i daje zrzuty ekranu (MCP `screenshot`, asystent AI w M6) bez dodatkowej ścieżki.
- **Ciała B-rep w dokumencie** jako rekord `solidcore_record::brep::Brep` (Clone/serde/Send) — undo, zapis
  projektu i writery STEP/IGES czytają tę samą formę; każda operacja dekoduje rekord do kernela i koduje wynik.
- **Komendy mesh-edit w MVP:** minimalny zestaw (import/eksport/transform/info/synth); rozszerzenia w M2+.

## Akceptacja
- `cargo xtask ci` zielone lokalnie i w GitHub Actions.
- Smoke test granicy kernela (`kernel::solid::tests::smoke_box_fillet_record`).
- Import odporny na wrogie wejście (`hostile_bytes_never_panic`, `hostile_headers_are_refused`).
- Te same komendy z GUI i CLI (`ui-egui/tests/gui_commands.rs`, `surfacecraft-cli/tests/cli.rs`).
